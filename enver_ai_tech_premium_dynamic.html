Orange Farm Mapper

Tile-based geospatial platform for agricultural monitoring. PostGIS spatial queries, MVT tile serving via pg_tileserv, MapLibre GL rendering — built for field operators on edge hardware.

PostGISpg_tileservMapLibre GLSupabaseGDALNext.js 14TypeScriptBetter Auth

What it does

Ingests GPS waypoints and drone imagery from field devices, stores plot geometry as PostGIS geography(POLYGON, 4326) with a GiST spatial index, and serves Mapbox Vector Tiles directly from the database via pg_tileserv. The client renders choropleth overlays in MapLibre GL — no tile CDN required.

Field operators see real-time health scores per plot, tile job status, and an area summary — all scoped to their account via Row-Level Security.

Technical architecture

Database · Supabase PostgreSQL + PostGIS extension
Geometry · geography(POLYGON, 4326) — WGS84 native
Spatial index · GiST on geometry column
Tile format · MVT via pg_tileserv — no CDN dependency
Renderer · MapLibre GL (open source, MIT licensed)
Auth · Better Auth sessions + RLS: farm_plots_owner
Ingest · GDAL for drone raster reprojection + vectorization
Frontend · Next.js 14 App Router · TypeScript strict · Tailwind

Key features

Plot geometry management

Draw, edit, and store farm plot polygons. Stored as PostGIS geography with full spatial query support including area, distance, and intersection queries.

Real-time health scoring

Per-plot health scores computed from sensor data and drone imagery analysis. Updated on each field device sync.

MVT tile serving

pg_tileserv serves vector tiles directly from PostGIS — no intermediate tile generation step, no S3 dependency, no tile CDN cost.

Per-user data isolation

RLS policy ensures each operator sees only their own plots. Enforced at database query time — not just application layer.

Resume Comparer

Upload two PDFs, get a cosine similarity score, skill gap delta, and structured diff. pgvector HNSW index with OpenAI ada-002 embeddings. P95 under 50ms on cold queries.

pgvectorHNSW indexOpenAI ada-002Supabase Storagepdfjs-distDrizzle ORMNext.js 14

What it does

You upload two PDF resumes. The system extracts text via pdfjs-dist, chunks it, embeds each chunk with OpenAI's text-embedding-ada-002 (1536 dimensions), and stores the vectors in a pgvector HNSW index in Supabase.

Similarity is computed as cosine distance across chunk pairs. The result is a percentage match score, a list of skills in A but not B, and a ranked similarity breakdown by section.

Technical architecture

Storage · Supabase Storage — private bucket, user-scoped prefix
PDF parsing · pdfjs-dist in a Supabase Edge Function
Embedding · OpenAI text-embedding-ada-002 · 1536-dim
Vector index · pgvector HNSW (m=16, ef_construction=64)
Distance metric · cosine · operator <=>
Latency · P95 <50ms · P99 <120ms (cold query)
Auth · Better Auth + RLS: resumes_owner + chunks_via_resume
ORM · Drizzle ORM · postgres-js driver · strict typed

Key features

PDF upload and storage

Files go to Supabase Storage under a user-scoped key. Never accessible cross-user. RLS enforced at storage policy level.

Cosine similarity scoring

HNSW index computes cosine distance across 1536-dimensional vectors. Fast even at scale — index doesn't degrade linearly.

Skill gap delta

Structured output listing skills present in one resume but absent from the other. Useful for hiring decisions and candidate ranking.

Full data isolation

RLS policies cascade from resumes → chunks → comparisons. No cross-user data exposure at any layer of the stack.
